# claude-code-telegram v1.3.0 — Integrated Security Assessment

- **Audited tree:** `overwirehq/claude-code-telegram` tag `v1.3.0`, commit `d6c07a03b159e452501ce14635afaec904a37e19`
- **Review date:** 2026-11-25
- **Detailed reports:** [Runtime review](v1.3.0-runtime-review.md) and [installation/dependency/CI review](v1.3.0-supply-chain-review.md)
- **Wayfinder map:** https://github.com/sn3akyLynx/claude-code-telegram/issues/1

## Bottom line

No malicious code, backdoor, covert telemetry sender, or undisclosed outbound endpoint was found in the repository's own v1.3.0 code. The telemetry and Sentry settings are inert. Expected traffic is to Telegram and, through the Claude CLI, Anthropic; build/CI traffic goes to package and GitHub services. Model-initiated Bash, WebFetch/WebSearch, MCP, and the Claude CLI's own behavior remain separate trust and data-egress surfaces.

The release nevertheless has **real security weaknesses and should not be deployed unchanged in a production or multi-user setting**. The most urgent are fail-open development authentication, callback authorization bypass, directory escape, and the gap between advertised tool controls and actual pre-execution enforcement.

## Priority findings

1. **High in classic mode — callback queries bypass authentication, security validation, and rate limiting.** Offline execution of the real bot handlers showed an unauthorized user reading directory listings and `git diff`. In default agentic mode the direct impact is lower, but unauthorized `cd:` callbacks remain possible. See runtime F-01.
2. **High when authentication is not explicitly configured — the default development profile fails open.** With `ENVIRONMENT` unset and `ALLOWED_USERS` empty, arbitrary Telegram users authenticate even when `DEVELOPMENT_MODE=false` is explicitly set. Production mode instead fails closed. See runtime F-02.
3. **High when webhook processing is enabled — third-party webhook text reaches an unattended Claude agent.** GitHub signature validation authenticates delivery, not the user-controlled issue/comment text inside it. Default tools include Bash, Write, WebFetch, and WebSearch. Model compliance was not tested. See runtime F-03.
4. **Medium-High — tool validation is not a preventive control.** Validation runs after tool dispatch, its exception is swallowed, and Bash inspection is skipped in agentic mode. Default sandbox exclusions include general execution primitives such as `git`, `npm`, `pip`, `poetry`, `make`, and `docker`. See runtime F-04/F-05.
5. **Medium — agentic `/repo` and `cd:` accept absolute paths and `..`.** Offline PoCs confirmed escape from `APPROVED_DIRECTORY`. See runtime F-07.
6. **Medium — the Claude CLI inherits bot secrets.** The process environment can include Telegram, Anthropic, and webhook credentials, creating a serious exfiltration consequence if model-driven commands are injected. Locked SDK 0.1.39 could not be fetched; subprocess behavior was checked with SDK 0.1.44. See runtime F-06.
7. **Medium supply-chain risks.** CI regenerates the dependency lock instead of testing committed hashes, Actions use mutable tags, the release workflow grants write permission to its dependency-installing test job, and installation docs recommend a force-moved `latest` ref. Fourteen locked packages had OSV advisory hits at review time; most application reachability is limited. The critical `claude-agent-sdk` resume-injection advisory was not found reachable from Telegram-controlled session IDs. See supply-chain F1–F6 and §4.

Additional conditional/low findings cover Telegram webhook authentication, webhook API resource limits, repo-local Git config execution, latent archive extraction, exported HTML escaping, plaintext persistence, and disabled CI workflow hazards. The detailed reports preserve severity prerequisites and negative findings.

## Verification performed

- Confirmed exact audited commit and only report files in research commits.
- Re-ran offline PoCs for fail-open authentication, classic callback data exposure, agentic callback/path traversal, and absolute-path `/repo` escape using fake tokens and temporary directories.
- Re-ran the upstream unit suite: **380 passed, 10 warnings**. Tests used `claude-agent-sdk==0.1.44` because locked 0.1.39 did not resolve from the package index at audit time.
- Directly checked source for middleware registration, authentication fallback, tool-validation order, sandbox exclusions, webhook-to-agent flow, and CI lock/action permissions.

## Limits of assurance

This was a static/source-led review with offline PoCs, not a live Telegram/Anthropic test or a formal guarantee of exploit absence. The Claude CLI binary, third-party package internals, full git history, and live Telegram callback behavior were not audited. No live service credentials were used. Dependency advisories are a point-in-time OSV snapshot from 2026-11-25. The fail-open PoC produced all expected assertions but its process did not exit before the parent command timeout; this did not affect the reproduced result.

## Recommended disposition

Block production use until runtime F-01, F-02, F-04/F-05, and F-07 are remediated and tested. Before enabling webhooks, also address F-03/F-09. Then harden secret inheritance and CI/dependencies. Voice implementation can continue on a separate branch, but it should not be treated as making the upstream security baseline safe.
